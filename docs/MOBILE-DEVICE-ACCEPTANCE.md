# VEGA: тестовая сборка и приёмка на телефонах

По решению пользователя от 29 октября 2026 приёмка на физических телефонах
отложена. Текущий приоритет — [3D-конфигуратор](3D-CONFIGURATOR.md).
Инструкция сохранена для возобновления; статусы не повышены до «пройдено».

Это подготовка этапа 2, не завершённая native-приёмка. В облачной рабочей среде
нет Android SDK/эмулятора и macOS/Xcode; APK/IPA здесь не собраны и не установлены.
Тестовые профили EAS подготовлены, но облачные сборки не запускались.

## Что проверяется автоматически

`pnpm check:mobile:native` генерирует настоящие проекты Android/iOS во временной
папке через установленный Expo и закреплённый шаблон
`expo-template-bare-minimum@58.0.30`. Проверяет идентификаторы, HTTPS-политику iOS,
исключение ненужных разрешений и настройки SecureStore backup на Android.
Существующие исходники и package.json не перезаписываются; временная папка удаляется.
Нужен доступ к npm для получения шаблона. CocoaPods/Gradle, подпись, APK/IPA и
устройства эта команда не проверяет. Проверка добавлена в CI mobile-customer.

Android светлая тема требует `expo-system-ui`; установлена версия 58.0.6 из
совместимого набора SDK58. Камера, микрофон, геолокация, внешнее хранилище и Face ID
текущим сценариям не нужны. SecureStore не использует биометрический вход.

## Перед сборкой

- Установить Node/pnpm по корневому README, выполнить frozen install.
- Подготовить изолированный demo API с PostgreSQL, тестовыми товарами и auth;
  настоящий рабочий аккаунт покупателя не нужен. Правила запуска — AUTH.md.
- API должен иметь действительный HTTPS-сертификат и быть доступным с телефона.
  Проверить `/health/ready` с телефона. Localhost на телефоне означает телефон.
- Владельцу войти в Expo/EAS и создать или связать проект. Не передавать ключи
  Apple/Expo в чат, не коммитить сертификаты и пароли.
- Идентификатор `com.vegappf.mobile.preview` временный, только для тестовых сборок.
  Идентификаторы магазинов и владелец ещё не согласованы.

Файл `eas.json` закрепляет EAS CLI 27.1.0. Профиль `preview` создаёт внутреннюю
Android APK или iOS ad hoc сборку; `simulator` — iOS Simulator сборку, которую
нельзя установить на физический iPhone. Production-профиля и автопубликации нет.

## Windows: подготовка EAS

В PowerShell из корня репозитория:

```powershell
pnpm install --frozen-lockfile
pnpm check:mobile:native
Set-Location apps/mobile
pnpm dlx eas-cli@27.1.0 login
pnpm dlx eas-cli@27.1.0 init
```

`init` создаёт/связывает внешний проект под выбранным владельцем и дописывает
projectId в конфигурацию. Сейчас projectId в репозитории нет. Проверить изменения
перед коммитом; не подставлять чужой projectId. Лимиты и условия облачных сборок
зависят от аккаунта Expo.

В EAS выбрать окружение `preview` и создать публичную переменную
`EXPO_PUBLIC_API_URL` с настоящим HTTPS origin своего demo API. Это адрес без
`/api/v1`, query, пароля или секретов. Значение встраивается в приложение:
оно не является секретом. Изменение endpoint требует пересборки.
`EXPO_PUBLIC_ALLOW_HTTP_DEMO=false` уже задан в профиле.

Hook `eas-build-post-install` проверяет endpoint и собирает workspace-пакет
контрактов до Metro. Пустое значение, localhost, HTTP и адреса-заглушки отклоняются.
Эта проверка подтверждает формат, а не доступность API или доверие его сертификату.
Сборка не получает доступ к производственным данным только из-за наличия URL.

## Android: установка тестовой APK

Из `apps/mobile`:

```powershell
pnpm dlx eas-cli@27.1.0 build --platform android --profile preview
```

После успешной сборки открыть выданную EAS ссылку на Android и скачать APK.
Разрешить установку этого тестового пакета выбранному браузеру, установить и
пройти сценарии ниже. Это обходится без Android Studio на Windows. Облачная
сборка может потребовать настройки подписи владельцем проекта.

## Физический iPhone

Нужны Apple Developer account и зарегистрированный тестовый iPhone для ad hoc
подписи. Apple-сборка может выполняться в EAS из Windows; локальный Xcode не нужен.
Из `apps/mobile`:

```powershell
pnpm dlx eas-cli@27.1.0 device:create
pnpm dlx eas-cli@27.1.0 build --platform ios --profile preview
```

Владелец регистрирует устройство по инструкции EAS и настраивает подпись под своим
Apple team. После успешной сборки устанавливает по ссылке EAS. Это не TestFlight
и не публикация в App Store. При добавлении нового устройства нужна новая
provisioning-конфигурация/пересборка. Без Apple-учётной записи, API и projectId
готовую устанавливаемую ссылку здесь обещать нельзя.

Expo Go не заменяет проверку самостоятельного приложения с его подписью,
идентификатором, разрешениями и SecureStore.

## Сценарии приёмки

| Сценарий | Ожидаемое поведение | Результат на устройстве |
|---|---|---|
| Холодный запуск гостем | Главная, изображение и навигация доступны; нет лишних запросов разрешений | Не проверено |
| Каталог и поиск | Реальные demo товары, категории, поиск, пустой результат и повтор загрузки | Не проверено |
| Карточка | Длина конкретного рулона и характеристики, возврат сохраняет фильтр | Не проверено |
| Подбор | Целые метры 1–18/рулон, позиции сохраняются после закрытия процесса | Не проверено |
| Регистрация | Телефон/пароль; статус ожидания одобрения; менеджера покупатель не выбирает | Не проверено |
| Сессия | После закрытия процесса токен восстанавливается из SecureStore, пароль не восстанавливается | Не проверено |
| Одобрение/отзыв | Изменение тестового статуса на сервере видно после foreground/обновления; цена и stock не выдумываются | Не проверено |
| Потеря сети | Безопасная ошибка и повтор; нет ложного успеха сохранения/выхода | Не проверено |
| Выход | Серверная сессия отозвана, SecureStore очищен, после перезапуска вход не восстановлен | Не проверено |
| Прерывание приложения | Background/foreground во время входа/обновления не возвращает старый профиль | Не проверено |
| Клавиатура и Back | Поля/кнопка доступны; Android Back закрывает карточку и возвращает на главную | Не проверено |
| Размеры и доступность | Safe Area, системный крупный текст, TalkBack/VoiceOver, портретный экран | Не проверено |
| Android backup | Восстановление приложения не поднимает старый bearer; токен SecureStore исключён из backup | Не проверено |

Проверить минимум физические iPhone и Android. Версии ОС, модель, номер сборки,
сеть и каждый фактический результат записать. Скриншоты не должны содержать
реальных покупателей, токены или пароль. Не ставить «пройдено» по web-скриншоту.

## Фиксация дефектов и завершение

Для дефекта: устройство/ОС/сборка → шаги → ожидание → факт → безопасный скриншот.
Исправление → новая сборка → повтор проблемного сценария и затронутых регрессий.
Приёмка этапа 2 закрывается только по фактическим результатам устройств и дизайна.
Известный node-forge audit остаётся отдельным блокером выпуска; native prebuild
и успешная тестовая сборка не отменяют обязательные проверки безопасности.
