# VEGA: десктопная админка каталога

> Актуальные бизнес-правила: [DECISIONS.md](DECISIONS.md). Сотрудники целевого
> продукта работают в 1С; описанные desktop-функции остаются demo-стендом.



Архивный demo-срез `/admin` в общей тёмной теме VEGA. Он исключён из целевого
релиза: сотрудники будут работать в 1С. Корень web ведёт в клиентский прототип,
переход из профиля в админку убран. Прямой demo URL сохраняет прежние staff ACL
для воспроизводимости тестов; это не production-панель управления.

## Функции среза

- Таблица товаров, поиск по названию/артикулу, категория и статус публикации.
- Создание и редактирование названия, артикула, описания, категории, ширины,
  длины конкретного рулона и публичных характеристик.
- Характеристики вводятся строками «название — значение», без редактирования JSON.
- Новый товар по умолчанию черновик; опубликованный виден в гостевом каталоге.
  Снятие с публикации скрывает список и публичную карточку товара.
- Создание категорий; удаления и переименования категорий в этот срез не входят.
- Версия товара предотвращает потерю параллельных изменений. Конфликт409
  сохраняет несохранённый ввод в редакторе, не перезаписывая другую версию.
- Успешные изменения и событие аудита сохраняются одной транзакцией. История
  содержит исполнителя, действие, объект, версию и время, без паролей/токенов.

Фотозагрузка реализована в demo (PRODUCT-MEDIA.md). Работа с заказами, цены,
реальные остатки, 1С и оплата ещё не подключены. Локальная публикация карточки не означает доступность товара
в 1С или возможность заказа. Приходящие из 1С данные редактор не подменяет.

## Доступ и запуск

Роль manager проверяется API по текущему пользователю при каждом запросе.
Регистрация всегда создаёт customer; HTTP-операций выдачи роли сотрудника нет.
Одного скрытия кнопок недостаточно: API запрещает операции гостям и клиентам.
Сессия остаётся в Secure/HttpOnly cookie, Bearer используется только сервером.

Сотрудник создаётся offline-командой `pnpm demo:admin:provision`. В изолированной
БД `_test`/`_demo` нужно применить миграции (`pnpm db:migrate`), включить demo-auth
и передать `ADMIN_PHONE`, `ADMIN_PASSWORD`, `AUTH_RATE_LIMIT_SECRET` через
локальное окружение. Не помещать значения в Git/аргументы команды/чат.
Существующий номер команда не повышает в правах и не перезаписывает.
Production runtime остаётся закрыт. Учётка не считается SMS-подтверждённой.

## Проверки

`pnpm test:integration` включает отдельный настоящий PostgreSQL admin-набор.
`pnpm test:admin` поднимает собственную схему/API/Next и проверяет desktop-flow.
Для UI используются Node24.19 и pnpm10.34.8; перед browser-набором собрать API
и admin. Cookie остаётся Secure и в локальных проверках loopback.
Публичный многопользовательский допуск требует решения trusted BFF source,
подтверждения номера, восстановления и общей security-приёмки (см. AUTH.md).

Категории для редактора загружаются полностью по100 за запрос: в этом demo
поддерживается до1000 категорий, суммарное ожидание ограничено10 секундами.
При превышении лимита экран явно отказывает, не подставляет неполный список и
не заставляет переносить товар в другую категорию. Фотозагрузка добавлена отдельным demo-срезом.
