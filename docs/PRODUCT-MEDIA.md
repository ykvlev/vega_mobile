Сотрудник загружает JPEG/PNG/WebP в существующую карточку товара. Не более 8 фото,
исходник до 5 MiB и 16 миллионов пикселей. SVG, анимация и повреждённые файлы не
принимаются. Расширению имени или MIME недостаточно доверять: проверяется
сигнатура до декодирования и формат после него. Sharp приводит изображение к
WebP, убирает метаданные, учитывает ориентацию и ограничивает размер 2048 px и 1 MiB.
Оригинальное имя и исходные bytes не сохраняются. Преобразование ограничено
одной активной задачей и двумя ожидающими.

## Хранение и видимость

Для изолированного demo обработанные bytes хранятся в PostgreSQL bytea вместе
с ограниченными метаданными. Это выбранный временный backend, не заявленная
production/CDN-инфраструктура. В дальнейшем объектное хранилище потребует
согласованной миграции, резервного копирования и политики хранения.

Снимки черновика доступны текущему manager. Посетитель получает bytes только
для опубликованного товара. Удаление, перестановка и добавление используют CAS
по версии продукта и транзакционный аудит. При конфликте или отказе проверки
версия и список фото не меняются. Смена порядка определяет главное фото.

`PUBLIC_MEDIA_ORIGIN` задаёт канонический origin ссылок API; Host запроса его
не определяет. Браузер работает с `/media/<UUID>` того же web-приложения.
Proxy всегда обращается к настроенному AUTH_API_URL, не к хосту из ссылки.
Токен доступен только серверу; черновики не попадают в HTML через публичный API.
Ответы и proxy используют no-store/nosniff, оптимизатор Next для этих фото
отключён, чтобы после снятия с публикации не оставалась доступная cached-копия.

## Web-загрузка

POST gateway проверяет Origin и текущую роль до чтения формы. Ограничен
фактический поток тела 6 MiB, а не только Content-Length; внутри допускается один
файл 5 MiB, ID товара и версия. Глобальный 1 MiB лимит Next Server Actions не поднят:
большой файл идёт через отдельный Route Handler. Авторизация API также стоит
перед multipart parser. Несохранённые поля и конкурирующие операции блокируют
медиа-действия, чтобы обновление версии не стирало ввод редактора.

## Проверка

`pnpm test:integration` включает настоящий PostgreSQL media-набор.
`pnpm test:media` запускает отдельную схему и API 3201 / Next 3105. Fixture-снимки
создаются Sharp; для UI дополнительно используется исходная авторская иллюстрация
автомобиля из проекта. Тесты не сохраняют auth traces или реальные credentials.

Локальная проверка финального среза: 32 unit/tooling, 32 PostgreSQL integration,
3 media browser и 7 admin regression тестов прошли без пропусков. Также прошли
production web build, lint, typecheck и проверка форматирования. Исправлена
гонка освобождения очереди при обрыве загрузки во время повторной авторизации;
есть детерминированный unit-тест. Выбор файла доступен после гидратации формы.
Удалённый CI проверяется отдельно; известный upstream node-forge audit blocker
не отключён и не считается исправленным этим срезом.
