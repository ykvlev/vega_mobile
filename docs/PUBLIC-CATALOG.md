# Гостевой каталог: независимый тестовый срез

Брендбук ожидается. Временная тема использует общие тёмные токены; этот срез
не означает приёмку этапов 1–3 или допуск к продаже.

## Что реализовано

- GET `/api/v1/categories`, `/api/v1/products`, `/api/v1/products/:id`.
- Буквальный поиск по названию и артикулу без учёта регистра, категория,
  ограниченная cursor-пагинация по ID. `%`, `_` и обратная косая черта не
  становятся поисковыми шаблонами.
- Строгие публичные DTO: цены, остатки и приватная metadata не выбираются из БД.
- `/catalog-lab`: серверное чтение API, поиск, категория, карточка с длиной
  конкретного рулона и шириной. Фотографии пока не подключены.
- Серверная переменная `CATALOG_API_URL`, GET/no-store, timeout 2 секунды,
  запрет redirects; внутренние адреса и исключения не выводятся посетителю.

Это отдельный технический экран, а не подключённая коммерческая главная.
Запись товаров сотрудниками требует авторизации и проверки ролей. Цены после
входа, реальные остатки 1С, корзина, резерв и оплата сюда не входят.

## Локальный запуск

Использовать закреплённые Node/pnpm, установить зависимости и создать `.env`
из `.env.example`, сохранив собственные значения. Затем:

```sh
docker compose -f infrastructure/compose.yaml up -d --wait
pnpm db:migrate
pnpm demo:catalog:seed
pnpm dev:api
# В другом терминале:
pnpm dev:admin
```

Открыть `http://localhost:3000/catalog-lab`. Demo seed создаёт две категории
и три явно демонстрационных товара. Он разрешён только при APP_MODE=demo,
COMMERCE_ENABLED=false, NODE_ENV!=production и имени БД с суффиксом `_test`
или `_demo`; существующие записи не перезаписывает, конфликт идентичности
останавливает транзакцию.

## Проверка

`pnpm test:catalog` требует собранных contracts/API/admin и явной тестовой БД.
Браузерный harness создаёт случайную схему, применяет миграции, наполняет её
и запускает собственные API3171/Next3101. После завершения удаляет свою схему.
CI выполняет этот сценарий в отдельном job `catalog-lab`, сохраняя screenshots
и traces на 7 дней. Общий security gate сохраняется: HIGH node-forge блокирует
quality job и релиз. Его нельзя считать пройденным по результатам этого job.

Проверка зависимости 24 октября 2026: registry latest node-forge=1.4.0,
официальный advisory GHSA-86w9-cpqp-85rv не указывает исправленную версию.
Последние Expo58.0.19 / CLI58.1.15 также сохраняют зависимость. Путь снятия
блокировки — upstream fix/release, обновление, полный audit и повторные проверки;
альтернативная смена toolchain требует отдельного обоснования и тестирования.

Локальная приёмка среза: contracts5/5, APIunit4/4, tooling6/6,
PostgreSQLintegration8/8, browsercatalog7/7, browserdesign7/7; lint,
format, typecheck и production-сборка admin прошли. После исправления
шрифтозависимых стрелок повторно пройден соответствующий browser320pxсценарий.
Это результаты локальных проверок; удалённый CI проверяется отдельно.
