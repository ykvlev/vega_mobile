Статус: серверный demo-срез реализован и локально проверен. Удалённый CI
проверяется отдельно; это не является релизным допуском.

Телефон + пароль — подтверждённый способ входа первого релиза. Этот срез
готовит серверные механизмы, а не публичную регистрацию или полноценный
допуск к продажам. Production runtime и commerce остаются запрещены.

## Границы

Авторизация по умолчанию выключена (`AUTH_DEMO_ENABLED=false`). Включение
требует явного demo-режима, тестовой/demo БД и отдельного случайного секрета
`AUTH_RATE_LIMIT_SECRET` длиной не менее 32 байт. Секрет не хранится в Git.

Номер нормализуется для входа, но не считается подтверждённым. Новый аккаунт
получает только роль customer. Нельзя привязать его к существующему клиенту
1С, чужим заказам или разрешить восстановление доступа по одному знанию номера.
SMS, recovery, refresh, browser cookies и клиентский экран входа — отдельные задачи.

## Серверные механизмы

- Строгие register/login DTO с телефоном и паролем, без роли или verified.
- Асинхронный scrypt, случайная соль, сравнение hash через timingSafeEqual.
  Параметры N=131072, r=8, p=1; ограниченная очередь защищает память процесса.
- Случайный opaque bearer-токен (32 байта), только SHA-256 digest в БД.
  Фиксированный TTL24 часа и отзыв текущей сессии. Токен передаётся заголовком,
  не в query. Ответы авторизации не кэшируются.
- PostgreSQL обеспечивает атомарные ограничения запросов между экземплярами
  API: login5 на номер и20 на источник за15 минут, register3 за час.
  Ключи счётчиков — HMAC от нормализованных значений. X-Forwarded-For не доверяем.
- Неизвестный номер и неверный пароль получают одинаковый401; для отсутствующего
  номера выполняется dummy KDF. Duplicate-register409 остаётся ограничением
  изолированного демо: полной защиты от enumeration здесь не заявляем.
- Телефон, пароль, bearer и внутренние ошибки не попадают в логи/ответы ошибок.
  Отказ БД не включает обход лимитов или process-local fallback.

Даже вход в demo-аккаунт пока не открывает реальные цены/остатки и не создаёт
резервов, оплат или заказов. Для публичного релиза нужны решение о подтверждении
владения номером и восстановлении, TLS/session storage клиентских приложений,
проверка abuse/retention и независимая приёмка безопасности.

## API этого среза

| Метод и путь | Результат |
| --- | --- |
| POST `/api/v1/auth/register` | 201: unverified customer и новая сессия; duplicate409 |
| POST `/api/v1/auth/login` | 200: новая сессия; одинаковый401 для неверных credentials |
| GET `/api/v1/me` | Только allowlisted user текущей bearer-сессии |
| POST `/api/v1/auth/logout` | 204: текущая сессия отозвана; повтор действующей отозванной сессии204 |

Register/login принимают только `{phone,password}`. Допустимые RU-записи номера
нормализуются в `+7XXXXXXXXXX`, пароль сохраняет пробелы и Unicode:15–128
кодовых точек, максимум512 UTF-8 bytes. Body JSON ограничен8KiB. Сессия
возвращается как `{token,expiresAt}`; на сервере токен не хранится открыто.
Неизвестная/истёкшая bearer-сессия получает401. Любые query-параметры авторизации
отклоняются. При выключенном модуле endpoints возвращают404.

Создание пользователя и первой сессии — одна транзакция после KDF. Если запись
сессии отказала, аккаунт не остаётся частично созданным. Лимиты запросов при
этом сохраняются отдельной транзакцией. Счётчики используют фиксированные
временные окна, часы PostgreSQL и ограниченную очистку окон старше24 часов.
Пока не реализованы политика удаления истёкших сессий и пользовательское
управление всеми сессиями; это остаётся частью подготовки публичного запуска.

## Результаты проверки

Контракты7/7, APIunit7/7, tooling6/6 прошли. Независимый QA выполнил
10/10 auth-проверок на настоящей PostgreSQL: два процесса API, перезапуск,
лимиты, повреждённый/большой JSON, mixed-case URL, expiry/revoke, отказ БД
и транзакционная регистрация. Старый APIintegration-набор8/8 также прошёл.
Временные auth-схемы после завершения отсутствуют.

Повторные browsercatalog7/7 и browserdesign7/7 прошли. Lint, format,
workspace typecheck и сборки API/admin/mobile web export прошли; native-сборку
этот результат не заменяет. Независимый критик просмотрел исходники; найденная
частичная регистрация исправлена и воспроизведена отдельной QA-регрессией.
Внешний gate node-forge сохранён. Клиентский вход ещё не подключён.
