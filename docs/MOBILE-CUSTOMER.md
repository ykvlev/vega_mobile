# VEGA: клиент на React Native

`apps/mobile` теперь содержит клиентские экраны на React Native/Expo, а не WebView
с сайтом: главная, каталог, карточка, подбор и аккаунт. Стиль — белые поверхности,
линейные поля и прямые кнопки LIMÉ. Главная использует локальную авторскую
автомобильную иллюстрацию; реальные материалы заказчика ещё потребуются.

## Реализованный срез

- Публичные категории и товары из существующего Nest API, поиск, фильтр,
  пагинация и карточка; цена/наличие не подставляются из fixtures.
- Длина рулона и ширина из публичного DTO, выбор целых метров 1–18 либо рулонов.
  Подбор — список материалов, не заказ и не подтверждение наличия.
- Подбор сохраняется между запусками через AsyncStorage. Проверяются версия,
  строгие публичные DTO, уникальность SKU/единицы и количественные ограничения.
  Максимум 50 позиций и 256 KiB — технический лимит локального подбора.
- Телефон + пароль, регистрация pending, актуальное одобрение из API, обновление
  статуса, выход с отзывом серверной сессии. Покупатель менеджера не выбирает.
- Состояния загрузки, ошибки/повтора, пустого результата и недоступной сети.
  Safe Area, клавиатура и Android Back обработаны средствами React Native.

## Сессия и приватность

На iOS/Android bearer и expiry сохраняются через Expo SecureStore. На iOS задана
доступность WHEN_UNLOCKED_THIS_DEVICE_ONLY, keychainService одинаков при чтении,
записи и удалении. Native plugin добавлен в app.json; зависимости подобраны по
bundledNativeModules.json установленного Expo58 и закреплены в lockfile.

В web-export bearer живёт только в памяти и теряется после reload. Это тестовая
поверхность RN-кода, не новый публичный browser login. AsyncStorage содержит
только публичные выбранные товары; пароль, телефон аккаунта и сессия туда не идут.
При неудачном отзыве/удалении сессии выход не объявляется успешным. Восстановление
и сохранение защищены поколениями операций и сериализацией I/O: старый результат
не перезаписывает новую сессию/подбор после cleanup/remount. На foreground профиль
проверяется снова через API. Это не заменяет серверный ACL коммерческих запросов.

API origin задаётся явно через EXPO_PUBLIC_API_URL, это не секрет. Разрешены HTTPS
и loopback HTTP для web-теста либо native development. Native release принимает
только HTTPS. Частный LAN HTTP разрешён только
в development при EXPO_PUBLIC_ALLOW_HTTP_DEMO=true. Продакшену не разрешён такой
обход; проверки TLS не отключаются. Изображения привязаны к настроенному API и
не получают bearer. API проверяет строгие DTO, объём ответа, отмену/таймаут и
не следует redirect с токеном. Реальные 1С, offers, заказы и платежи не добавлены.

## Запуск и проверка

Сначала установить workspace, собрать контракты, поднять demo API и применить
миграции по корневому README. Auth по умолчанию выключен; изолированная настройка
описана в AUTH.md. Не использовать реальные клиентские credentials в demo.

На физическом телефоне localhost — сам телефон, не компьютер. Нужен достижимый
с телефона HTTPS origin API. Для Windows PowerShell, после настройки своего API:

```powershell
$env:EXPO_PUBLIC_API_URL = 'https://your-demo-api.example'
pnpm dev:mobile
```

Адрес выше — обозначение собственного сервера, не готовый VEGA endpoint.
Expo Go/development build должен соответствовать SDK58 и установленным native
модулям; native-приёмка на устройствах ещё требуется. Локальный HTTP в LAN может
дополнительно ограничиваться настройками development client/операционной системы.
Native dependencies и endpoint меняют сборку; подписанные приложения не выпущены.

Для локальной проверки RN-компонентов через Chromium:

```sh
EXPO_PUBLIC_API_URL=http://127.0.0.1:3106 pnpm build:mobile
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium pnpm test:mobile
```

Harness поднимает собственную PostgreSQL-схему/API3202 и static web3106, использует
фиксированный ограниченный same-origin proxy только для тестов и удаляет свою
схему/процессы. `EXPO_PUBLIC_API_URL` задаётся до export: Expo встраивает значение.
Эти порты не являются устройственным backend для production. Trace авторизации
выключен. Screenshot artifacts не содержат реальных покупателей.

Lifecycle unit-набор исполняет транспилированные исходники с минимальными doubles
React hooks/storage и отложенным API: это детерминированная проверка гонок, а не
настоящий React renderer или устройство. Сквозной набор отдельно проверяет
реальные RN web-компоненты с Nest/PostgreSQL. Компиляция JS для iOS/Android не
является APK/IPA, запуском на устройстве или разрешением магазина.

## Следующая приёмка

Физические iPhone/Android, SecureStore и возврат из background, системная клавиатура,
крупный текст, экранная клавиатура/скринридер и устойчивость сети. Затем контракт
и тестовая база 1С, получение реальных каталог/одобрение/назначение, согласованный
процесс изменений заказа, эквайринг и доставка. Известный upstream node-forge
остаётся в общем аудите: он не скрывается отдельным mobile job.
