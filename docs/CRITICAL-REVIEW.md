# VEGA — независимый критический review

Статус: финальный документарный review этапа 0 после обновления решений и API.
Приложения, тесты и деплой ещё не реализованы. Закрытие замечаний ниже относится
к спецификациям, а не к runtime-проверкам. Проверены DECISIONS, ROADMAP,
API-CONTRACT, BACKEND, PAYMENTS, MOBILE, ARCHITECTURE, QUALITY-PLAN и SECURITY.

## Вердикт этапа 0

**Документарных блокеров перехода к bootstrap не обнаружено.** Это не разрешение
production-продаж, не security sign-off приложения и не заявление «всё работает».
Незавершённые внешние подключения и будущие испытания перечислены отдельно.

## 1. Метры и рулоны одного SKU — закрыто по документам

Исходный пробел: позиция корзины адресовалась только SKU, семантика сочетания
метров и рулонов не была определена. Исходная severity — medium.

[API-CONTRACT.md:51](/workspace/vega_mobile/docs/API-CONTRACT.md:51) задаёт lineId,
unique(cartId, skuId, unit), две независимые строки для метров/рулонов и проверку
совместной доступности на весь заказ. Изменение/удаление адресуется по lineId.
[MOBILE.md:83](/workspace/vega_mobile/docs/MOBILE.md:83) и BACKEND.md согласованы
с этим правилом. Повторный POST устанавливает абсолютное количество и не
прибавляет его молча.

**Не выполнено:** реализация и тесты добавления, изменения, удаления двух unit
одного SKU, конкурентной правки и отсутствия двойного резервирования остатка.
Это gate будущего этапа корзины, а не оставшийся документарный blocker этапа 0.

## 2. Неизвестный результат заказа — закрыто по документам

Исходный пробел: mobile требовал предварительный lookup, которого не было
в backend-контракте. Исходная severity — medium.

[API-CONTRACT.md:127](/workspace/vega_mobile/docs/API-CONTRACT.md:127) фиксирует
один протокол: сохранить исходные account-scoped endpoint/key/payload до запроса;
после timeout/перезапуска повторить тот же POST без отдельного lookup. Описаны
REQUEST_IN_PROGRESS, Retry-After, конфликт payload, replay до новой проверки
истёкшего quote, tombstone/expired record и запрет автоматического нового ключа
при неизвестном результате. MOBILE.md и BACKEND.md используют тот же протокол.

**Не выполнено:** lost-response + restart E2E, конкурентный replay, expired
quote/key без дубликата, сохранность/изоляция pending-контекста между аккаунтами.
Retention/recovery window требуют численных значений до production; локальные
fixtures не утверждают рабочие значения.

## 3. Строгий gate QA — закрыто по документам

Исходная severity — high для объявления этапа принятым.
[QUALITY-PLAN.md:112](/workspace/vega_mobile/docs/QUALITY-PLAN.md:112) определяет
PASS/FAIL/BLOCKED для конкретных scope, SHA, артефакта и окружения. PASS требует
исправления всех найденных дефектов этапа и независимого retest с регрессией;
неисполненная обязательная проверка не считается пройденной. TEAM.md закрепляет
запрет продвижения при FAIL/BLOCKED и не разрешает оркестратору обходить gate.

**Не выполнено:** настройка GitHub required checks/rulesets/environments и проверка
на намеренно падающем тесте. Документ не является техническим enforcement.

## Перепроверенные актуальные правила

- При <=2 целых рулонах новая нарезка из целых запрещена; готовый отрез можно
  продать, если он покрывает требуемую непрерывную длину. Нельзя складывать
  несколько коротких обрезков и выдавать их за один длинный.
- Первый вход — телефон+пароль. SMS позже. До рабочих аккаунтов обязательны
  защита от перебора, безопасное подтверждение владения и recovery.
- Гость не получает цены/остатки и производные коммерческие сведения, включая
  приватный кэш после logout.
- 1С обязательна для реальных продаж: quote/submit проверяют актуальную доступность;
  отсутствие SKU/остатка, stale/unavailable дают отказ без коммерческого Order.
  Успешный submit не обещает резерв до оплаты.
- Менеджер согласует условия до оплаты; клиент принимает точную версию.
  Перед оплатой — повторная проверка и подтверждённое товарное обязательство 1С,
  защищающее от других каналов. Отправка только после подтверждённых 100% средств.
- Money передаётся строкой целого минимальных единиц валюты, длина — строкой целых
  миллиметров; UI и API не используют binary float для финансовых расчётов.
- Внутренние скриншоты pushr уже просмотрены. Прежнее ограничение «есть только
  карточка App Store» снято; сходство финального UI проверяется отдельно.

## Что остаётся вне допуска этапа 0

Внешние blockers production: доказанный протокол 1С и общего резерва, merchant
и источник подтверждения оплаты счёта, фискальная схема, условия доставки,
TTL/retention, безопасный account recovery, инфраструктура и аккаунты публикации.
Это не требует остановить bootstrap на явно тестовых данных.

Будущие runtime gates: рабочие сборки Android/iOS/API/admin, ACL/cache leak,
конкурентные резервы, payment webhook/refund/expiry races, 1С contract E2E,
restore/rollback, мониторинг и фактические защиты GitHub. Они пока не пройдены.

## Полномочия критика

Проверять каждое направление и оркестратора; требовать факт, последствия и
проверяемое закрытие вместо авторитетного «готово». Возвращать результат при
конкретном невыполненном критерии. Не выдумывать уязвимости, не раздувать MVP
и не подменять QA/security. Строгость направлена на решения и доказательства,
а не на личные оскорбления. Новые подтверждённые находки могут изменить вердикт.
